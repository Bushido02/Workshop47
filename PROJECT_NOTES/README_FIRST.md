# Что это за архив

Это твой мод Reign of Nether с добавленной фракцией **Formix** (рабочий +
воин, конвертация между ними, своё здание) и отдельной системой прокачки
персонажа игрока (не юнита-героя). Изначально это был минимальный
MVP-пайплайн для обкатки процесса, но проект уже вырос за рамки MVP —
подробности всегда актуальны в журнале, не здесь.

## С чего начать

1. Открой `PROJECT_NOTES/FORMIX_FACTION_LOG.md`, раздел
   **"0. АКТУАЛЬНОЕ СОСТОЯНИЕ"** (самое начало файла) — это подробный,
   постоянно обновляемый журнал: что сделано, что временное (placeholder),
   какой баг сейчас активен, что делать дальше. **В следующий раз, когда
   попросишь продолжить работу над модом — дай мне сначала прочитать этот
   раздел**, тогда я не буду заново разбирать архитектуру с нуля.
2. `PROJECT_NOTES/QUICK_REFERENCE.md` — практические рецепты типовых
   правок (текстура/модель/юнит/здание/баланс) и честный статус про
   работу с GitHub. Держи вместе с журналом, они дополняют друг друга.

3. Собери проект и проверь, что он компилируется:
   ```
   ./gradlew build
   ```
   или через IntelliJ IDEA / другую IDE. Код пишется без доступа к живому
   Forge/Minecraft окружению (только сверка вручную с существующим кодом
   проекта), так что ошибки компиляции возможны. Если что-то не
   соберётся — пришли текст ошибки, поправлю.

4. Запусти игру, зайди в лобби выбора фракции — там должен появиться
   Formix. 3D-модели worker/warrior пока простые placeholder'ы (под
   будущие Blockbench-модели), но иконки в UI и названия ресурсов
   ("Рис"/"Эфир"/"Версиформ") уже используют реальный арт и текст.

## Известный незавершённый баг (на момент последнего обновления)

Population supply у `FormixHive` иногда показывает 0 — причина не
найдена, в коде сейчас стоят два временных диагностических лога, ждущих
`run/logs/latest.log` после теста. Подробности и что именно прислать —
в разделе "0. АКТУАЛЬНОЕ СОСТОЯНИЕ" журнала.

## Про Blockbench-модели

Ты сказал, что уже делаешь модели worker и warrior в Blockbench. Когда они
будут готовы:
1. Экспортируй как Java Entity (File → Export → Export Java Entity) и
   отдельно анимации (File → Export → Export Animations).
2. Пришли мне эти файлы (или опиши, что экспортировалось) — я вставлю их
   на место заглушек. Подробная инструкция — в разделе 4.1
   `FORMIX_FACTION_LOG.md`.

## Про здание

Главное здание фракции (`FormixHive`) сейчас использует чужую схематику
(структуру Villagers' Town Centre), чтобы можно было тестировать геймплей
уже сейчас. Когда сделаешь свою постройку — раздел 4.2 в логе объясняет,
как её подключить (это буквально замена одной строки в коде + добавление
файла `.nbt`).

## Если хочешь работать через Claude Projects

Чтобы не объяснять контекст проекта заново в каждом новом чате:

1. Создай Project в claude.ai (или используй уже существующий).
2. Открой `CLAUDE_PROJECT_INSTRUCTIONS.md` — там, между строками
   `=== НАЧАЛО ===` и `=== КОНЕЦ ===`, готовый текст. Скопируй его в поле
   **Instructions** проекта (Project → Settings → Instructions).
3. В раздел **Knowledge** (файлы проекта) загрузи `FORMIX_FACTION_LOG.md`
   и `QUICK_REFERENCE.md` — оба обязательны, инструкции ссылаются на них.
4. Дальше просто открывай новый чат внутри этого проекта каждый раз, когда
   продолжаешь работу над модом — не нужно заново прикладывать архив или
   объяснять, что уже сделано.
5. **После каждой сессии, где менялся `FORMIX_FACTION_LOG.md` или
   `QUICK_REFERENCE.md`** — обнови их и в Project Knowledge (Files →
   удалить старую версию → загрузить новую), иначе в следующем чате
   Claude увидит устаревшую версию и будет предполагать неверное
   состояние проекта. Project Knowledge не синхронизируется с репозиторием
   автоматически — это ручное действие с твоей стороны.
